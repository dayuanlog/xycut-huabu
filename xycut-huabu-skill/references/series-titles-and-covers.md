# 标题、封面与正文时间偏移

竖屏制作默认读取本规范。横屏用户要求固定标题、统一系列包装或前置封面时也可使用；具体版式仍由输出模式决定。

## 标题确认

用户明确给出或已确认本期视频标题时，直接使用，并依输出比例合理分行；不要再次要求确认。用户只给出系列名、主题、脚本、文件名或模板示例标题，不能视为已确认本期标题。系列名与期数可以沿用已给定内容，但缺少本期标题时应结合实际文案提出约3个简洁、真实且不同侧重点的候选，请用户选择或自行提供。明确区分视频标题、系列名和封面副标题；用户已提供的部分直接保留，不擅自更改含义或杜撰效果、数字。

等待标题选择期间可继续ASR、素材分析、画布与动画规划等不依赖标题的工作。标题未确认前不得将候选当作最终封面文字或片内固定标题定稿，也不导出带未确认标题的成品；用户选择、自拟标题或明确授权自行决定后继续。已有工程的小幅调整保留已确认标题，只有用户要求重新拟题才重新提候选。用户明确不需要标题和封面时无需询问。

## 模板与本期内容分开

Skill保存字体层级、位置、安全区、封面帧数和时间映射方法。项目保存主标题、可选系列名／期数、本期副标题、封面分行与其他本期文案。下一视频按自己的文案设计组件，不继承示例中的主题、金额、素材、页数或音效数量。

项目可沿用已使用的`series`字段保存标题；单片也可使用该结构并省略期数。下面是字段示意，生成时填写真实内容，不把占位文字放进成片：

```json
{
  "series": {
    "title": "本项目主标题或系列名",
    "episode_label": "第1天",
    "subtitle": "本期副标题",
    "cover_lines": ["副标题第一行", "副标题第二行"]
  },
  "intro": {"frames": 5, "duration": 0.16666666666666666}
}
```

顶部第一行组合主标题与非空期数，第二行显示本期副标题。空期数不留下分隔符。主副标题都应清楚醒目；封面将副标题放到最大层级，主标题和期数作为识别信息。具体标题名字不是竖屏模式的固定要求。

期数默认使用阿拉伯数字；示意中的“第1天”按项目改成相应期数，普通单片可省略。竖屏片内标题与字幕靠近中央1:1正文，但互不遮挡。片内标题默认左对齐、无装饰图标，位置与字号见[竖屏制作](portrait-framing.md)。

封面应按**视觉主题与叙事形态**做差异化设计，避免所有模板千篇一律只有左对齐纯文字：

- **竖屏封面（9:16）**：核心标题与视觉主体严格居中于**中央 3:4 安全区**（`1080×1920` 下左右留白约 `116px`，垂直围绕中心分布），兼顾 9:16 播放与平台 3:4 列表裁切不截断。
  - **纯配音版**：主副标题 + 迷你画布结构缩略图 / 主题标签卡片，一眼体现画布风格。
  - **人物主导版**：全屏人物实拍杂志构图 + 上下柔光渐暗压底 + 主题标题与标签条（裁切避开原图边角水印）。
  - **人物小窗版**：画布结构卡片与人物立卡并排/分栏组合，直观呈现「画布为主 + 人物小窗陪伴」。
- **横屏封面（16:9）**：采用左右双栏海报构图（左侧主副标题与特性标签，右侧迷你画布预览窗或人物立卡），不套用竖屏窄版式。

下一集替换本期标题、期数、分行、强调词与数字，保留已确认的版式与主题风格。用户要求其他比例时按其比例另作检查。

横屏与竖屏均默认使用 **5 帧完整静态封面**（`intro: { frames: 5, duration: 5/fps }`，音频预留同长 `media_timing.audio_lead`），封面从第 0 帧即完整可见，不在这 5 帧内慢慢打字揭示；可另存同款 `cover.png`。预览工作台支持一键开关封面，用户指定其他帧数、时长或明确取消封面时按其要求。

## 两个时间坐标

仅制作独立封面时，不插入正文、不创建音频偏移，也不需要ASR。封面比例与尺寸单独记在封面工程或输出清单，不修改原视频的output；没有指定像素时，3:4可用1080×1440、16:9可用1920×1080作为起点，用户尺寸优先。按封面自己的比例检查标题层级、边距和裁切安全区；用户要求静态HTML时保存HTML并截图，按要求交付PNG等图片。

下文时间规则只用于把封面插入视频的任务。

以项目最终fps计算：

```javascript
const lead = intro.frames / output.fps;
const contentTime = Math.max(0, presentationTime - lead);
const finalDuration = contentDuration + lead;
```

- `renderAt(t)`与进度条使用最终播放时间，`window.END`为最终总时长。
- 组件动作、镜头、字幕、语义锚点、画板和组件局部起点继续使用正文时间。源ASR及其`timeline_revision`不改写。
- `content_duration`表示整个正文的设计时长，含正文内已规划的无配音片尾；`duration=content_duration+intro.duration`。不要在两处重复计算片尾。
- 章节按钮和局部预览边界加同一偏移。批注记录最终播放秒数，需要定位ASR时同时保留正文秒数。
- 封面阶段独立显示封面层，隐藏正文、顶部片内标题和字幕；自由浏览隐藏封面，能完整查看画布。

## 音轨与BGM

配音、音效、混音及“仅听原音”试听都在开头补同长静音。48kHz音频的5帧/30fps对应8000个采样；其他fps按实际采样数计算。重新生成从无前缀来源读取，避免重复加静音。音效事件同时保留正文时刻与最终播放时刻。

有BGM时，音乐避让的人声活动区间也必须转换到最终播放时间。`mix_bgm.py`的偏移和输出文件用法见[声音规范](presentation-and-sound.md)。检查播放器实际读取的混音格式与路径，不能只生成MP3却仍试听旧WAV。

播放器使用音频时钟时，监听结束事件并停止播放，处理音频采样时长与设计时长的微小舍入差异；最后一帧渲染到最终总时长。

## 集成边界与验证

共享`assets/runtime/camera.js`提供framing取景，`subtitles.js`提供字幕工厂；共享演示播放器本身不负责配音或自动消费intro。复制运行时后要在本次工程接入封面UI、正文时间映射、固定标题、字幕与已加前缀的音轨，不能只填JSON便宣称完成全部功能。

先验证第0–4帧显示封面、第5帧进入正文，再检查一个真实ASR锚点、字幕、章节跳转、局部播放、随机回跳、音频静音前缀和片尾停止。总览静态排版也要独立检查。渲染fps与output.fps一致，不能按30fps设计5帧后用60fps直接导出。
